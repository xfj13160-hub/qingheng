# 轻衡 · 小程序前端

基于 uni-app、Vue 3、TypeScript、Vite 和 Pinia 的饮食与健身记录工具。包含网页与微信小程序构建；所有记录只保存在当前设备。没有账号、服务器、云同步、AI 识别或付费接口。

新增每日饮食计划：按客户的增肌、减脂或维持目标，估算热量和三大营养素，并生成标明克数、生熟状态的一日参考菜单。计算规则、研究依据、适用边界与本次验证见 [DAILY_NUTRITION_PLAN.md](./DAILY_NUTRITION_PLAN.md)。

## 运行网页

建议使用 Node.js 20.19+ 或 22 LTS、npm 10+。

```bash
cd qingheng
npm ci
npm run dev
```

浏览器打开 <http://127.0.0.1:5173/>。首次进入可设置个人信息和目标，也可跳过。没有内置的饮食、身体或训练示例记录。

```bash
npm run type-check   # TypeScript 与 Vue 模板检查
npm test             # 计算、存储事务、照片选择结果测试
npm run build        # 网页产物 dist/build/h5
npm run preview      # 预览已构建网页 http://127.0.0.1:4173/
npm run build:weixin # 微信产物 dist/build/mp-weixin
npm run dev:weixin   # 微信开发模式 dist/dev/mp-weixin
npm run assets       # 重新生成本地图标与食物插画
```

正式网页需通过 HTTP(S) 静态服务器打开，不能直接双击 index.html。使用 hash 路由，不需要额外的服务端路由重写。Vite CJS 弃用提示来自当前 uni-app 工具链，不影响构建；不要直接给 package.json 添加 `type: module`。

## GitHub Pages 部署

本仓库为轻衡的个人副本，包含每日饮食计划功能。网页地址以仓库 Settings → Pages 页面显示的地址为准。原项目：<https://github.com/yiming1001/qingheng>。

仓库的 Settings → Pages 使用 **GitHub Actions**。每次推送到 `main`，工作流会自动安装依赖、检查类型、运行测试、构建网页并发布；也可在 Actions → Deploy GitHub Pages 手动运行。部署结果和错误可在该工作流查看。

工作流通过 `actions/configure-pages` 获取站点子路径，并使用 uni-app 的 `UNI_H5_BASE` 设置资源路径，适配 `/qingheng/`。本地开发仍使用根路径；手动构建同样的 Pages 产物可执行 `UNI_H5_BASE=/qingheng/ npm run build`。

GitHub Pages 仅托管静态网页，不提供数据库、账号或云同步。饮食、训练、身体记录和照片仍只保存在访问者的浏览器中，不会上传到 GitHub。线上网址与本地预览的记录相互独立；换浏览器、换设备或清除站点数据不会自动恢复记录。截图目录仅含独立验收数据。

## 微信开发者工具导入

1. 在 `src/manifest.json` 的 `mp-weixin.appid` 填写你自己的微信小程序 AppID。
2. 执行 `npm run build:weixin`。
3. 打开微信开发者工具，选择“导入项目”，目录选择 **dist/build/mp-weixin**，使用相同 AppID。不需要开启云开发。
4. 当前交付产物没有配置正式 AppID，生成配置中为 `touristappid`；可先体验工具允许的游客模式，正式预览和真机能力需使用你的 AppID。
5. 在开发者工具和手机分别确认系统胶囊、日期选择、键盘遮挡、安全区域、照片选择及本地保存。构建成功不代表这些真机检查已完成。

源码使用 uni-app 的 view/text/input/picker/canvas 等跨端组件，并以条件编译隔离 H5 照片存储；微信端保留系统胶囊，不绘制模拟胶囊。本次没有进行 Android/iOS 打包或验证。

## 页面与使用路径

- **今日**：能量圆环、三大营养素、快捷记录、最近体重和有依据的本地建议。
- **饮食**：日期切换，早餐/午餐/晚餐/加餐，点击已记录食物进入编辑或删除；支持常吃、自定义及复制昨天。
- **训练**：周历、每日记录、每周次数/时长/运动天数；点击记录可编辑或删除。
- **我的**：个人与目标、每日饮食计划、身体趋势、常吃食物及每周回顾。
- **每日饮食计划**：根据客户资料与目标估算每日摄入，生成三餐及加餐，支持食物组排除、素食、更换搭配、复制、保存最近一份计划和确认后更新本机营养目标。计划不会自动计为实际饮食。
- **身体趋势**：体重/腰围/体脂，7/30/90 天，点击图表数据点查看数值；历史列表可进入编辑。

饮食照片仅作附件：选择后由用户手动填写食物与份量，可预览、更换和移除。复制昨天会提示已有记录及重复风险，追加昨天所有食物和份量，不复制照片。身体记录每日期一条，保存到已存在日期时会提示替换。

  services/      版本化本地仓库、照片持久化
  styles/        颜色、布局、按钮、表单与安全区域
  utils/         导航、确认框、数值校验

存储仓库通过 `StorageAdapter` 接口隔离平台能力；未来接后台可在 services 层增加远端仓库和同步策略，页面使用 store 操作记录。照片保存与解析独立于页面；需要云端同步时应另外设计上传、授权和迁移。

## 数据与计算口径

- 营养值 = 每100克参考值 × 实际克数 ÷ 100。汇总保留小数，显示时才四舍五入；历史饮食保存当时的营养快照，自定义食物以后更改不会重算旧记录。
- 内置食物为常见参考值，并非接入的权威实时数据库。品牌、含水量、烹饪油和酱料可能造成差异，以包装与实际称量为准。
- BMI = kg ÷ 身高米数²；身高或体重缺失时显示空值，不反推体脂。
- 七日均重只平均截止日及此前6天已有体重的日期，不补齐缺失日。
- 周回顾以周一至周日统计；热量达标为当前热量目标的 ±10%，蛋白质达标为达到当前蛋白质目标。平均热量只计算有饮食记录的日期；有记录不等于全天完整记录。
- 身体变化为所选时间段首末两条有效记录之差，少于两条时不显示变化结论。
- 建议基于当天已记录的食物和当前手动目标生成，说明计算依据，不根据没有记录推断吃得不足。

## 本地保存边界

文字记录使用版本化 `qingheng:data:v1` 本地存储。写入成功后才更新共享状态，写入失败显示反馈；读到损坏数据时保留原始内容并停止写入，避免空数据覆盖。

H5 照片以 Blob 保存在 IndexedDB，页面重开时重新解析；单张限制8MB。微信照片通过 `uni.saveFile` 保存，避免使用临时路径。平台配额或权限失败会提示，用户取消选择不会报错。

网页数据按“协议、主机、端口”隔离，5173 和4173、localhost 和127.0.0.1 的记录互不共享。清理站点数据、卸载小程序或系统清理存储会影响记录；本版本没有备份导出、账号恢复及跨设备同步。照片清理失败不会回滚已保存的记录，目前没有自动清理孤立附件的任务。
